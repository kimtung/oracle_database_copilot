Phase 1 — Core Milestones
1. Đủ 32 Oracle MCP Tools server.py
  • SQL (4): get_top_sql, get_sql_statistics, get_sql_wait_events, get_sql_execution_context.
  • ASH (2): get_ash_sample, get_ash_sql_activity.
  • AWR (2): get_awr_snapshot, get_awr_sql_stats.
  • Session (5): get_active_sessions, get_session, get_session_waits, get_blocking_sessions, get_long_running_sessions.
  • Plan (2): get_sql_plan, get_sql_plan_history.
  • Object (6): get_object_source, get_object_metadata, get_object_arguments, get_object_dependencies, get_dependency_graph, get_invalid_objects.
  • Storage (11): Tablespace, Datafile, Segment, Temp, Undo, Redo, Sysstat, Scheduler Jobs.
2. OracleMcpClient Gateway client.py
  • Giao tiếp IPC qua stdio với tiến trình oracle-mcp-server.
  • Gửi lệnh và nhận kết quả JSON-RPC chuẩn MCP SDK ClientSession.
  • Tự động đo thời gian phản hồi (duration_ms), bắt lỗi và ném McpClientError.
  • Tách bạch hoàn toàn backend db-copilot khỏi driver Oracle.
3. Evidence Normalizer evidence_normalizer.py
  • Chuẩn hóa số liệu thô từ Oracle thành đối tượng domain Evidence có cấu trúc.
  • Xử lý đa dạng: SQL Regression, Cây khóa chặn (Blocking Chain), Cảnh báo dung lượng Tablespace, Job lỗi, Object Invalid.
  • Gán đúng mức độ nghiêm trọng (Severity) và gắn cờ giả thuyết sơ bộ (supports_hypothesis).
4. Bộ Ba Data Collectors collectors/
  • SqlCollector: Kéo Top SQL, lấy execution stats, so sánh baseline phát hiện suy thoái.
  • SessionCollector: Quét active sessions, lọc session chạy lâu và bắt cây khóa chặn.
  • StorageCollector: Kiểm tra dung lượng tablespace (> 85%, > 95%), job lỗi và invalid objects.
5. Baseline Engine (2-Sigma) baseline_engine.py
  • Thu thập mẫu 7 ngày gần nhất phân bổ theo (Giờ trong ngày, Thứ trong tuần).
  • Lọc bỏ nhiễu ngoại lai (Outlier Removal) theo chuẩn phân phối thống kê: $\mu \pm 2\sigma$.
  • Tính toán các mốc chuẩn: Mean, P50, P95, Stddev cho Elapsed time, CPU time, Buffer gets.
  • Đánh dấu độ tin cậy (is_reliable khi mẫu $\ge 5$).
6. EvidenceScheduler (APScheduler) scheduler.py
  • Sử dụng AsyncIOScheduler chạy non-blocking trên event loop của Python.
  • Chu kỳ thu thập số liệu (SQL, Session, Storage): 5 phút/lần.
  • Chu kỳ tính toán lại đường cơ sở hiệu năng (Baseline): 1 giờ/lần.
  • Tích hợp tự động khởi động và tắt an toàn trong FastAPI lifespan.

Cơ Chế Lọc Nhiễu Ngoại Lai & Tính Toán Baseline (BaselineEngine)

Baseline của câu SQL được tính toán theo từng khung giờ trong ngày (0-23) và từng thứ trong tuần (0-6) để phản ánh đúng chu kỳ tải thực tế của doanh nghiệp: 

1. Thu thập tập mẫu: Dữ liệu thực thi của SQL_ID trong 7 ngày gần nhất cùng khung giờ/thứ.
2. Lọc bỏ Outliers (2-Sigma):
   - Tính mean μ và độ lệch chuẩn σ ban đầu.
   - Loại bỏ các giá trị nằm ngoài khoảng: [μ - 2σ, μ + 2σ].
3. Tính toán lại các mốc thống kê sau lọc:
   - mean_elapsed_ms   : Thời gian thực thi trung bình chuẩn.
   - p50_elapsed_ms    : Trung vị (Median).
   - p95_elapsed_ms    : Mốc phân vị 95%.
   - is_reliable       : Đánh dấu TRUE nếu số mẫu sau lọc >= 5, ngược lại FALSE.
4. Lưu trữ vào bảng `sql_baselines` trong PostgreSQL.
